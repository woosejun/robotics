# 📑 소프트웨어 소스 코드 구조 및 핵심 로직 설명서

본 문서는 플랫폼의 멀티스레딩(Multi-threading) 기반 비동기 시스템 아키텍처와 핵심 소스 코드의 상세 작동 원리를 설명합니다. 데이터 경합(Race Condition) 방지를 위해 `threading.Lock()`을 활용한 상태 관리가 적용되었습니다.

---

## 🏗️ 1. 시스템 아키텍처 및 데이터 흐름

전체 시스템은 역할에 따라 독립적인 스레드로 분리되어 병렬 처리되며, `shared_state.py`를 매개체로 데이터를 안전하게 공유합니다.

```
┌────────────────────────────────────────────────────────────────────────┐
│                              shared_state                              │
│  ┌─────────────────┐ ┌─────────────────┐ ┌──────────────┐ ┌─────────┐  │
│  │  current_frame  │ │   detections    │ │ target_hist  │ │ robot_  │  │
│  │  [frame_lock]   │ │   [data_lock]   │ │  [_hist_lock]│ │  state  │  │
│  └────────┬────────┘ └────────▲────────┘ └──────▲───────┘ └────▲────┘  │
└───────────┼───────────────────┼─────────────────┼──────────────┼───────┘
            │                   │                 │              │
    [Frame  │           [Update │         [Update │       [Read  │
    Update] │           Result] │         Master] │       State] │
            ▼                   │                 │              │
┌───────────────────────┐       │                 │              │
│     camera_thread     │       │                 │              │
│  (camera.py)          ├───────┼─────────────────┼──────────────┼───────┐
└───────────────────────┘       │                 │              │       │
                                │                 │              │       ▼
┌───────────────────────────────┴─┐               │              │ ┌───────────┐
│        inference_thread         │               │              │ │   Web     │
│  (inference.py / TensorRT)      ├───────────────┘              │ │ Monitor   │
└─────────────────────────────────┘                              │ │ (Flask)   │
                                                                 │ └───────────┘
┌────────────────────────────────────────────────────────────────┴┐      ▲
│                         control_thread                          │      │
│  (controller.py / LOST FSM)                                     ├──────┘
└─────────────────────────────────────────────────────────────────┘  [AJAX Fetch]
```

1. **`camera_thread`**: 하드웨어 가속 파이프라인(GStreamer)을 통해 고속 프레임을 취득하고 공유 프레임을 최신화합니다.
2. **`inference_thread`**: 최신 프레임을 가져와 TensorRT 가속 YOLOv8로 사람을 감지하고, HSV 히스토그램 유사도를 비교하여 타겟(주인) 인덱스를 추출합니다.
3. **`control_thread`**: 타겟의 이미지 좌표 오차를 기반으로 부드러운 필터링 오차를 계산하고, 유실 시 LOST FSM(유한 상태 기계)에 따라 추적 상태를 제어합니다.
4. **`web_tracker` (Flask)**: 브라우저로 실시간 이미지 스트리밍(MJPEG) 및 시스템 주행 상태(AJAX)를 송출하며, 마스터 등록 인터페이스를 제공합니다.

## 💻 2. 파일별 파일 가이드 및 핵심 로직

### ① `shared_state.py` (전역 동기화 및 데이터 상태 관리)
* **기능**: 여러 스레드가 공유 자원에 동시 접근하여 발생하는 데이터 왜곡을 방지하기 위해 상호 배제(Mutex) 락을 제공합니다.
* **주요 상태 변수**:
  * `frame_lock` / `current_frame`: 고속 이미지 데이터 스레드 세이프 공유용.
  * `data_lock` / `detections`, `sim_scores`, `target_idx`: YOLOv8 바운딩 박스 정보 및 현재 매칭된 마스터 인덱스 보호.
  * `target_hist_lock` / `target_hist`: 주인의 고유 복장 색상 히스토그램 정보 잠금.
  * `control_lock` / `control_error_x`, `robot_state`, `last_direction`: 최적화된 조향 오차 및 주행 상태 동기화.

### ② `camera.py` (하드웨어 가속 기반 고속 영상 취득)
* **기능**: Jetson Nano의 연산 자원을 절약하고 프레임 드롭을 방지하는 입력 파이프라인입니다.
* **핵심 로직**:
  * **GStreamer 하드웨어 파이프라인**: `v4l2src` 장치에서 이미지를 캡처하여 `jpegdec` 및 `videoconvert` 하드웨어 가속을 통해 CPU 점유율을 대폭 낮춘 채 BGR 프레임을 `appsink`로 전달합니다.
  * **예외 처리(Fallback) 로직**: GStreamer 파이프라인 오픈 실패 시, 일반 OpenCV V4L2 백엔드로 자동 전환되어 `MJPG` 포맷 및 해상도(`640x480`), FPS(`30`)를 수동 설정하여 캡처를 지속하는 이중 안정성을 구축했습니다.

### ③ `inference.py` (TensorRT 최적화 추론 및 고유 타겟 식별)
* **기능**: 엣지 디바이스 환경에서 초고속 Object Detection을 수행하고, HSV 색상 분포를 활용해 특정 타겟을 연속 추적합니다.
* **핵심 알고리즘**:
  * **TensorRT 엔진 가속**: `yolov8n.engine` 포맷 변환 모델을 로드하여 정밀도를 유지하면서 Jetson Nano 디바이스의 최적 프레임 연산 속도를 확보했습니다.
  * **HSV 히스토그램 ROI 추출 및 비교 (`get_hist`)**: 타겟 복장 색상을 정밀 분석하기 위해 전체 바운딩 박스 내에서 배경 간섭이 심한 머리·발끝을 제외한 상/하체 중심 영역(Y축 상위 25%~100%, X축 좌우 25%~75%)만을 관심 영역(ROI)으로 지정합니다. 16x16 빈(Bin)의 2차원 HSV 히스토그램을 생성 후 `cv2.compareHist(..., cv2.HISTCMP_CORREL)` 상관관계법을 통해 유사도 스코어($0.0 \sim 1.0$)를 도출합니다.
  * **지수 이동 평균(EMA) 기반 히스토그램 갱신**: 주행 중 조명 변화 및 역광에 대응하기 위해, 타겟 유사도가 `HIST_UPDATE_THRESHOLD (0.6)` 이상으로 매우 확실할 때 마스터 히스토그램을 매 프레임 부드럽게 누적 업데이트합니다.
    $$	ext{Target Hist}_{	ext{new}} = (1 -  eta) 	imes 	ext{Target Hist}_{	ext{old}} +  eta 	imes 	ext{Current Hist} \quad ( eta = 0.1)$$
  * **비동기 마스터 등록**: 웹의 `/save` 명령으로 `save_requested` 플래그가 참이 되면, 전체 감지된 객체 중 화면 중앙 정중앙선(`CENTER_X`)과 가장 가까운 객체를 마스터(주인)로 지정하고 고유 히스토그램을 초기화합니다.

### ④ `controller.py` (조향 필터링 및 LOST 유한 상태 기계)
* **기능**: 원시 비전 오차 데이터를 가공하여 조향 신호 안정성을 확보하고, 시야 유실 시 시간별 복구 시나리오를 구동합니다.
* **핵심 제어 알고리즘**:
  * **저주파 통과 필터 (Low-Pass Filter)**: 비전 프레임 급변이나 감지 노이즈에 의해 모터가 튀는 현상을 막기 위해 `ALPHA (0.15)` 계수를 적용하여 조향 타겟을 부드럽게 추종합니다.
    $$	ext{Virtual Error} = 	ext{Virtual Error}_{	ext{prev}} +  lpha 	imes (	ext{Raw Error} - 	ext{Virtual Error}_{	ext{prev}})$$
  * **변화율 제한기 (Rate Limiter)**: 제어 루프 주기(`CONTROL_DT = 0.03s`) 동안 한 번에 변화할 수 있는 최대 오차폭을 `MAX_STEP (15)` 이내로 강제 제한하여 물리 모터 구동부에 가해지는 순간 충격(Jerk)을 완화합니다.
  * **히스테리시스 조향 제어 (Hysteresis Logic)**: 제 정중앙 부근에서 로봇이 좌우로 미세하게 떠는 채터링(Chattering) 현상을 제거하기 위해 이중 문턱값을 적용했습니다. 오차가 `START_TURN (40)`을 초과해야 회전 상태(`turning=True`)로 진입하고, 회전 중 오차가 `STOP_TURN (20)` 이내로 좁혀져야 조향을 멈추고 직진 모드로 환원됩니다.
* **LOST 유한 상태 기계 (Finite State Machine, FSM)**:
  * **`TRACK` 상태**: 마스터가 정상 식별되는 상태이며 실시간 조향 오차 필터 제어를 수행합니다. 마스터 유실 시 즉시 `lost_start_time`을 기록하고 FSM 상태 연산으로 전환됩니다.
  * **`SEARCH` 상태**: 유실 직후 `SEARCH_TIME (1.0초)` 동안은 로봇의 주행을 즉시 정지하고 정지 상태를 유지하며 카메라 프레임 내 재진입을 대기합니다.
  * **`LOST_RIGHT` / `LOST_LEFT` 상태**: 유실 기간이 `LOST_RIGHT_TIME (3.0초)` ~ `LOST_LEFT_TIME (5.0초)`로 장기화되면, 주인이 직전에 사라졌던 마지막 방향(`last_direction` : 좌측 또는 우측)을 메모리에서 복원합니다. 해당 방향으로 제자리 회전 제어 오차(`SEARCH_ERROR = 120`)를 인위적으로 주어 능동적 시각 탐색을 실행합니다.
  * **`WAIT_UWB` 상태**: 유실 시간이 `5.0초`를 초과하여 시각적 탐색 한계를 넘어서면 로봇 주행 및 비전 제어를 완전히 일시정지하고, 고유 UWB 무선 측위 패킷 신호를 대기하며 센서 융합 하이브리드 모드로 진입합니다.

### ⑤ `visualization.py` & `web_tracker.py` (모니터링 및 웹 인터페이스)
* **기능**: 원격 제어 인터페이스 환경을 구축하고 비동기식 데이터 파이프라인을 시각화하여 모니터링 편의성을 높입니다.
* **핵심 로직**:
  * **`draw_frame` 가공**: 실시간 이미지 위에 전체 사람 바운딩 박스(청색), 마스터로 지정된 객체 박스(적색), 상하체 유사도 점수 텍스트, 카메라 정중앙선 및 마스터 오차 편차선(`ERR_X`)을 오버레이 렌더링합니다. 특히 `WAIT_UWB` 상태 진입 시 화면 정중앙에 크고 굵은 경고 배너를 출력합니다.
  * **MJPEG 저지연 스트리밍**: Flask 서버에서 대용량 동영상 코덱 연산 부하를 피하기 위해 `multipart/x-mixed-replace` 콘텐츠 타입을 사용하여 압축 처리된 JPEG 프레임을 브라우저에 실시간 푸시 스트리밍합니다.
  * **비동기 주행 상태 감시 (AJAX Fetch)**: 웹 페이지 템플릿 내부에서 JavaScript가 초당 10회 비동기식 요청을 생성하여 `/get_data` 라우트로부터 실시간 조향 제어 오차(`control_error_x`) 데이터를 수신하며, 전체 웹 화면 깜빡임 현상 없이 모니터링 정보를 갱신합니다.
