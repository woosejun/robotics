## 대회 당시 구현

### 영상으로 사람을 추종하는 카트

- **하드웨어 구성**은 Logitech C920 USB 카메라, Jetson Orin Nano, ESP32 모터 제어기, 모터 실드와 4륜 메카넘 플랫폼입니다.
- **사람 검출과 대상 등록**은 YOLOv8n·TensorRT를 사용했습니다. Flask 화면에서 등록하면 화면 중앙에 가까운 사람의 옷 색상 특징을 HSV 히스토그램으로 저장하고, 이후 검출 결과와 비교합니다.
- **조향과 거리 판단**은 검출 박스의 가로 중심 오차와 높이에서 계산했습니다. EMA로 순간 변화를 완화하고, 데드존과 히스테리시스로 경계 주변의 반복 회전과 출발·정지를 줄였습니다.
- **모터 출력**은 Jetson이 USB 직렬로 보낸 한 글자 명령을 ESP32가 바퀴 방향 패턴으로 바꾸는 구조였습니다. 당시 영상에는 복도에서 주행하는 카트와 추적 상태를 표시한 대시보드가 함께 나옵니다.

### 대회 종료 시점의 UWB

최종 발표자료 9쪽에는 UWB와 Jetson을 완전히 연동하지 못한 것으로 기록되어 있습니다. 대회 기간 기준 커밋에는 앵커·태그 스케치와 거리 수신 코드가 있으며, 당시 시연 범위는 영상 추종이었습니다. 발표자료의 실시간 추론 개선과 복도 시연은 대회 기록으로 설명할 수 있습니다. 실제 FPS와 정지거리는 동일 조건의 재현 계측이 필요합니다. [대회 기간 작업 기록](session_summary.md), [기준 코드와 이력](https://github.com/woosejun/robotics/commit/0f01a8efdf81725fba9ba030cada3ee34d826a78)

## 1차 보완

### 원본에서 재현한 문제와 대응

| 문제 | 모의 재현에서 관찰한 동작 | 수정 |
| --- | --- | --- |
| 영상 추론이 멈춘 뒤에도 전진 | 추론 오류 뒤 60초가 지나도 마지막 검출과 `F`가 유지됨 | 원래 촬영 시각을 전달하고 추론 오류 시 마지막 검출을 무효화. 영상 0.5초, 제어 명령 0.2초의 유효 기간을 송신 단계에서 확인 |
| 사용자 등록 전 탐색 회전 | 초기화 후 약 2.1초에 우회전, 약 8.1초에 좌회전 명령 발생 | 대상 등록과 운영자의 주행 활성화를 분리. 기본 탐색은 정지 |
| ESP32 응답 상실 | ACK가 1초 넘게 오지 않아도 이전 전진 명령을 계속 송신 | 초기 `OK S` 확인 후 주행 허용. 이후 ACK 만료 시 정지하고 재활성화 요구 |
| 가까운 대상의 영상 거리 판단 | 중앙에서 박스 높이 100px, 240px, 429px가 모두 전진. 430px에서 정지 분기가 먼저 적용되어 `NEAR`에 도달할 수 없었음 | 원시 박스 높이 430px 이상이면 정지. 원시값과 EMA가 모두 380px 이하일 때 해제 |
| 한쪽 UWB 표본이 끊긴 뒤에도 위치 계산 | 연결이 끊긴 쪽의 이전 거리와 다른 쪽의 새 값을 합쳐 좌표 갱신 | 앵커별 시각·ID를 검사하고, 오래되거나 단절된 거리와 불가능한 삼각형을 좌표 계산에서 제외 |

안전 정지와 등록 로직은 [영상 제어](../ai_vision/controller.py), [직렬 송신기](../ai_vision/robot_comm.py), [주행 회귀 테스트](../tests/test_motion.py)에 있습니다.

### UWB 수신과 펌웨어 보완

왼쪽 앵커 `ANCHOR1`과 오른쪽 앵커 `ANCHOR2`에서 거리 로그를 별도로 수신합니다. 두 앵커와 태그의 공통 무선 코드를 정리하고, 응답에서 앵커 ID와 시퀀스를 확인하도록 했습니다. 모의 시험에서는 줄이 나뉘어 들어오는 경우, 포트 ID 뒤바뀜, 한쪽 거리 만료, 재연결을 재현했습니다.

앵커 간격 0.30m, 왼쪽 거리 1.300m, 오른쪽 거리 1.217m를 입력했을 때 **우측 약 0.35m, 전방 약 1.20m**를 계산했습니다. 이 단계의 UWB 결과는 진단 도구와 대시보드의 위치 표시에 사용했습니다. [수신 코드](../ai_vision/uwb_comm.py), [앵커·태그 공통 코드](../uwb/libraries/CartUwb/src/cart_uwb.h), [수신 시험](../tests/test_uwb.py)

### 대회 모터 매핑을 이식할 수 있도록 정리

대회 카트에서 확인한 74HC595 비트를 바퀴와 회전 방향별 상수로 정리했습니다. 장비 교체 시 확인할 GPIO와 활성 극성, 바퀴별 비트 점검 모드를 문서화했습니다. 펌웨어 모의 시험에서는 부팅 정지, 명령 타임아웃, 장애물 해제 직후의 이전 명령 폐기를 확인했습니다. [모터 매핑표와 이식 절차](motor_setup.md), [모터 펌웨어 시험](../tests/firmware/motor_test.cpp)

**1차 검증 결과**는 Windows에서 Python 15개와 C++ 모의 시험 2개 통과입니다. Arduino CLI 1.3.1과 ESP32 코어 2.0.17에서 모터 스케치 1개와 UWB 앵커·태그 스케치 3개를 컴파일했습니다.

## 2차 UWB 모터 통합

### 이번에 추가한 주행 경로

좌우 앵커 거리 → Jetson의 좌우·전방 위치 추정 → 방위각과 거리로 주행 판단 → USB 직렬 → ESP32의 74HC595 모터 출력

| 태그 위치 또는 상태 | 명령 | ESP32 출력 |
| --- | --- | --- |
| 정면에서 멀리 있음 | `F` 전진 | `0xA3` |
| 카트 오른쪽에 있음 | `C` 시계 방향 회전 | `0xAC` |
| 카트 왼쪽에 있음 | `K` 반시계 방향 회전 | `0x53` |
| 가까운 거리 또는 정지 조건 | `S` 정지 | `0x00` |

주행에 쓰는 좌우 거리에는 앵커 ID가 필요하며, 두 거리의 수신 시각 차이는 최대 0.32초, 샘플 수명은 0.65초입니다. 처음 움직이거나 방향을 바꿀 때는 같은 판단이 나온 거리 쌍 두 개를 확인합니다. 짧게 구동한 다음에는 정지 상태에서 양쪽 거리를 다시 수신합니다. 0.85m 근거리 기준에서 정지하고, 정지 후에는 중심 거리 1.05m 이상과 최신 거리 조건을 확인해 다시 움직입니다. [UWB 주행 제어 코드](../ai_vision/uwb_drive.py), [기준값과 동작 설명](uwb_drive.md)

두 앵커 거리로 구한 위치에는 앞뒤 대칭이 있습니다. 기본 UWB 모드에서는 등록 대상이 카메라 전방에 보일 때 주행을 허용합니다. 앵커 단절, 입력 만료, 비정상 좌표 또는 정면 확인 상실이 발생하면 정지합니다. 앵커 재연결 후에는 운영자가 다시 활성화해야 움직입니다. [Jetson 설정과 벤치 시험](uwb_drive.md#jetson에서-연결)

## 소개 문장 예시

> 제9회 AI ROBOTICS 융합 아이디어 경진대회에서 Jetson Orin Nano와 ESP32를 사용해 카메라 기반 사용자 추종 카트를 팀으로 제작했습니다. 대회 후에는 오래된 추론 결과가 모터에 계속 전달되는 문제를 재현하고 정지 조건과 UWB 거리 수신을 개선했습니다. 이어 UWB 위치를 전진·회전·정지 명령으로 연결하고, 가상 앵커와 실제 ESP32 스케치의 모의 실행으로 모터 출력과 연결 장애 대응을 검증했습니다.
