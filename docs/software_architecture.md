# 소프트웨어 구조

`ai_vision/web_tracker.py`에서 Flask 대시보드와 카메라, 추론, 제어, 모터 직렬 통신 작업을 시작합니다. UWB 앵커는 좌우 포트를 각각 별도 작업에서 읽습니다.

| 경로 | 책임 |
| --- | --- |
| `camera.py` | USB 카메라를 열고 프레임과 단조 시계 기준 촬영 시각을 게시 |
| `inference.py` | 새 영상에 YOLOv8n 실행, 대상 등록 및 HSV 거리 비교, 원래 촬영 시각과 함께 결과 게시 |
| `controller.py` | EMA, 회전 히스테리시스, 박스 높이 기반 정지, 주행 활성화와 추적 상태 전환 |
| `robot_comm.py` | 직렬 ACK 확인, 명령과 영상의 유효 기간 검사, 만료 시 정지 송신 |
| `uwb_comm.py` | 앵커별 수신·재연결·유효 기간 관리, 좌표 계산 |
| `uwb_drive.py` | 정지 중 수집한 UWB 좌표로 조향·전진·정지 결정, 시야와 측정 만료 검사 |
| `web_tracker.py` | MJPEG 스트리밍과 상태 API, 등록·활성화·정지 POST |

## 추적과 정지

등록 요청 후 새 프레임에서 화면 중앙에 가장 가까운 검출을 선택합니다. 유효한 사람이 검출될 때까지 최대 5초간 기다립니다. 이후 비슷한 히스토그램이 여러 개면 유사도 차이를 검사합니다. 비슷한 옷, 조명 변화와 가림은 색상 기반 판별 정확도에 영향을 줍니다.

등록을 마치면 `READY`에서 정지합니다. 운영자가 활성화하고 모터 구동 시에는 `OK S` 조건도 만족해야 `TRACK` 상태가 됩니다. 마지막 추론에 쓰인 프레임이 0.5초 이상 오래되거나 제어 명령이 0.2초 이상 갱신되지 않으면 정지하고 활성화를 해제합니다. 모터 직렬 ACK가 1초 이상 오지 않는 경우에도 활성화를 해제합니다.

영상 모드에서 대상을 놓치면 `SEARCH`에서 정지합니다. 2초 후에도 대상을 찾지 못하면 `WAIT_UWB`로 넘어가 정지하고 활성화를 해제합니다. 탐색 회전은 `SEARCH_ROTATION_ENABLED`를 명시적으로 켠 경우에만 수행됩니다. UWB 제어는 실행 시 `ROBOTICS_FOLLOW_MODE=uwb`로 선택합니다.

박스 높이 430px 이상에서는 원시 측정값으로 즉시 정지합니다. 정지 상태를 해제하려면 원시값과 EMA가 모두 380px 이하여야 합니다. `FAR`와 `TARGET`은 영상 거리 구간이며 고정 속도 실드에서는 같은 전진 마스크를 사용합니다.

## UWB에서 모터까지

앵커 포트 스레드는 주행용 측정 쌍을 생성할 때 양쪽 ID, 시차와 갱신 여부를 검사합니다. 제어 루프가 좌표에서 방위를 구하고 두 측정 쌍에서 같은 방향이 확인되면 짧은 모터 명령을 생성합니다. 명령이 끝나고 차체가 멈추면 두 앵커를 다시 읽습니다. 직렬 송신 루프가 센서·명령 만료와 동작 시간 제한을 독립적으로 확인한 뒤 ESP32로 한 글자를 보냅니다. [UWB 동작과 시험 조건](uwb_drive.md)

## 잠금과 장애 검증

프레임과 촬영 시각은 동일한 프레임 잠금으로 게시합니다. 등록과 주행 상태를 동시에 변경할 때는 데이터 잠금, 제어 잠금, 직렬 상태 잠금 순서로 접근합니다. 모터 송신부는 제어 루프와 별개로 정지를 집행할 수 있습니다. 케이블이 끊긴 경우 ESP32 타임아웃이 정지를 담당합니다.

가상 직렬 테스트에서 UWB 거리 데이터의 분할 수신·순서·재연결 및 모터 ACK 상실을 재현합니다. 모델 추론 성능과 주행 중 정지거리는 실제 장비에서 측정해야 합니다.
