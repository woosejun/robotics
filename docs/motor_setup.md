# 모터 실드 매핑과 장비 이식

[ESP32 스케치](../motor_control/esp32_usb_controller/esp32_usb_controller.ino) 맨 위의 하드웨어 프로필에 대회 카트에서 실측한 값을 모았습니다. 방향 기준은 카트 뒤에서 전방을 바라본 방향입니다.

| 바퀴 | 전진 비트 | 후진 비트 |
| --- | --- | --- |
| 왼쪽 앞 | `0x80` | `0x40` |
| 왼쪽 뒤 | `0x20` | `0x10` |
| 오른쪽 앞 | `0x02` | `0x04` |
| 오른쪽 뒤 | `0x01` | `0x08` |

| USB 명령 | 동작 | 74HC595 출력 |
| --- | --- | --- |
| `S` | 정지 | `0x00` |
| `F` | 전진 | `0xA3` |
| `B` | 후진 | `0x5C` |
| `L` | 오른쪽 바퀴만 전진해 좌측 코너링 | `0x03` |
| `R` | 왼쪽 바퀴만 전진해 우측 코너링 | `0xA0` |
| `C` | 시계 방향 제자리 회전 | `0xAC` |
| `K` | 반시계 방향 제자리 회전 | `0x53` |

USB 직렬은 115200 baud와 단일 ASCII 문자 명령을 사용합니다. 시동, 명령 타임아웃, 장애물 해제 후에는 정지 명령 `S`를 먼저 보내 `OK S`를 확인합니다. Jetson은 50ms 간격으로 명령을 보내고, ESP32는 500ms 동안 유효한 명령이 끊기면 모터를 정지합니다. ACK는 수신한 명령을 펌웨어가 처리했다는 응답입니다.

## 새 장비에서 바꾸는 부분

1. 스케치 상단의 `DATA_PIN`, `STCP_PIN`, `SHCP_PIN`, `EN_PIN`과 구동기 enable 극성을 확인합니다. 기존 실드는 low에서 enable되고 `MSBFIRST`를 사용합니다. 부팅 동안의 전기적 차단이 필요하면 실드 enable 입력에 적합한 하드웨어 풀업 또는 차단 회로를 적용합니다.
2. 바퀴를 들어 올리고 `ENABLE_BIT_MAPPING_TEST`를 임시로 켭니다. 직렬 모니터에서 `S` 뒤에 `1`부터 `8`까지 한 번에 하나씩 보내 실제 바퀴와 회전 방향을 기록합니다. 각 시험 뒤 `S`를 보냅니다. 새 비트를 각 바퀴 상수에 반영하고 테스트 모드를 끕니다.
3. 초음파 `TRIGGER_PIN`, `ECHO_PIN`, 부저 핀과 설치 높이를 확인합니다. 20cm는 기존 정지 기준입니다. 기본 `STOP_ON_MISSING_ECHO=false`는 반사체가 없는 경우를 허용하며, 이 설정에서는 센서 단선도 에코 없음으로 처리됩니다. 단선을 정지 조건으로 다루려면 에코가 항상 들어오는 설치인지 확인한 뒤 옵션을 조정하거나 별도 감지를 추가합니다.
4. 모터 명령 방향, 장애물 접근 및 제거, 케이블 분리, 전원 재인가를 차례대로 시험합니다. 차체 조건에 따라 속도와 정지거리를 실측합니다. 모터 마스크 시험은 보드에서 실제로 움직이는 방향을 확인해야 완료됩니다.

이 펌웨어는 고정 속도 방향 마스크를 구동합니다. PWM 속도 제어나 메카넘 횡이동을 쓰는 차체는 해당 실드의 속도 제어 및 바퀴 구동 패턴을 추가해야 합니다.

## 컴파일과 모의 실행

```bash
arduino-cli compile --fqbn esp32:esp32:esp32 motor_control/esp32_usb_controller
g++ -std=c++11 -I tests/firmware tests/firmware/motor_test.cpp -o motor_test
./motor_test
```

C++ 모의 실행은 실제 스케치의 출력 마스크와 부팅·타임아웃·장애물 해제 동작을 검사합니다.
